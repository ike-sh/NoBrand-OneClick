## 流量及凭据

- 六个受管节点同时运行。使用 sing-box 1.14.1 读取管理器导出，分别验证 Snell v4/v5/v6 和 SS2022 AES-128、AES-256、ChaCha20。每组 TCP 回显 32,768 B；普通 UDP 回显 64、512、1,200 B。检查目标端计数和逐字节一致性；不是只检查端口打开或握手成功。
- 六组错误 PSK/密钥均未到达目标，换回正确凭据后数据恢复。删除节点后同端口可重新绑定。SS2022 仅 TCP 模式下验证 TCP 可用、UDP 端口未占用且即使用此前允许 UDP 的客户端配置也无法转发。
- Snell v5 为 Surge 导出 5、为 sing-box/Mihomo 导出 4；v6 为 Surge/sing-box 导出 6、明确拒绝 Mihomo。v5 的额外 UDP 套接字只预留端口，不作为对外 QUIC 功能。未测试 Surge 实机或 QUIC；不对所有客户端作兼容承诺。
- Mihomo 1.19.30 的 SS2022 AES-128/256 各通过 5/5 轮对照，TCP/UDP 均可用。ChaCha20 首轮在 1.19.30 出现一次 32,768 B TCP 无回显；随后在 5 组节点/密钥上对 1.19.30 和 1.19.32 分别做冷启动对照，各通过 15/15 次 64 B TCP、15/15 次 32,768 B TCP、15/15 组 UDP（每组三包）。同节点和密钥的 sing-box 前后对照均通过。首次失败未定位，不将 ChaCha20 + Mihomo 标为无条件兼容。
- SS2022 密钥只在显式导出中出现。IPv6/域名、URI 转义、特殊节点名、三种方法的 Base64 编码/实际长度，以及仅 TCP 不能生成分享 URI，由格式与负例回归覆盖。本轮新协议的实流验证为 IPv4 回环。

## 升级、恢复和所有权

- 用真实 v4.2.0 管理器和官方 v0.6.5 建立包括 Mieru BOTH、Snell 4/5 和认证 SOCKS5 在内的 9 个监听器。升级拒绝隐式建立 witness；显式接受基线后新内核 revision 仍为 12，节点、inbound/binding/account ID、Vault 主密钥、旧客户端凭据和展示端点不变。
- 分别在原始、升级、重启、整代回滚、带 witness 备份恢复、旧备份显式确认后恢复这六个阶段，重用**升级前**的 Snell v4/v5 和 SOCKS5 配置验证 TCP/UDP。坏 witness 或 pending witness 保留现场并拒绝使用。
- 新协议集合上注入候选端口健康故障，旧凭据与端口恢复、新端口释放。AES-128 节点备份→轮换→删除→恢复后，原 key 重新可用，轮换后的 key 被拒绝；真实数据库/witness 路径保留六个原生资源 ID。
- 在隔离 user/net/PID namespace 运行单文件 CLI，覆盖创建、状态/Doctor 脱敏、统一备份、变更、统一恢复、删除与统一卸载。init 和防火墙后端使用测试替身；规则所有权、管理器事务、校验、进程与磁盘文件用实际代码，未声称验证过宿主发行版的防火墙配置。

## 复核入口

在带 Git 历史的 Linux AMD64 checkout 运行。`ASSETS_067` 和 `ASSETS_065` 分别是该发行版的 Linux AMD64 tar、RELEASE_MANIFEST.json 和 SHA256SUMS 所在目录；测试客户端使用固定发行包而不是开发构建。

```bash
bash scripts/build.sh --check
NOBRAND_SPLICORE_PUBLIC_ARTIFACTS="$ASSETS_067" \
NOBRAND_REFERENCE_SING_BOX_ARCHIVE="$SING_BOX_1_14_1_ARCHIVE" \
NOBRAND_REFERENCE_MIHOMO_GZIP="$MIHOMO_1_19_30_GZIP" \
bash scripts/test.sh --runtime

# 非特权用户创建临时 user/net namespace，使用生产路径的数据库备份/恢复。
unshare --user --map-root-user --net sh -c 'ip link set lo up && exec "$@"' sh \
  python3 tests/helpers/probe_protocols_v43.py --native-storage \
  --artifacts "$ASSETS_067" --sing-box-archive "$SING_BOX_1_14_1_ARCHIVE"

unshare --user --map-root-user --net sh -c 'ip link set lo up && exec "$@"' sh \
  python3 tests/helpers/probe_splicore_v067_upgrade.py --artifacts "$ASSETS_067" \
  --old-artifacts "$ASSETS_065" --mihomo-gzip "$MIHOMO_1_19_30_GZIP"
```

一轮既有 HY2 证书测试在新签发证书的 `notBefore` 边界失败；隔离重现实验在 1,120 次签发/校验中捕获 4 次相同的 OpenSSL error 9，均对应 WSL 墙钟回拨约 1.1 秒。对刚刚签发的受管证书，仅遇到该错误时在单调时钟 3 秒窗口内重新运行完整 OpenSSL 验证；没有成功验证仍然失败，过期或签名不匹配不靠重试放行。未关闭有效期校验或放宽证书断言。

范围不含 ARM64、移动设备、公网长期连接、宿主 systemd/OpenRC 实机认证或整套上游内核资格重测。
